# set-direction

방향은 사람이 정한다. 이 스킬은 근거를 모으고 판정과 권장안을 낸다. 판단 기준은 [d3-core.md](../../references/d3-core.md), 경로는 [paths-and-templates.md](../../references/paths-and-templates.md), 방향이 바뀔 때의 전파는 [change-propagation.md](../../references/change-propagation.md)를 따른다.

## 1. 모드 고르기

| 요청 | 모드 |
|---|---|
| 방향 문서가 없거나 비어 있음 | 초안 |
| 기능·작업이 방향에 맞는지 | 판정 |
| 기존 기능 전체를 방향에 대입 | 점검 |
| 대상 사용자·문제·가치를 바꾸자는 요청이나 근거 | 변경 |

`PRODUCT.md`를 먼저 읽는다. 없으면 지어내지 않고 「방향 문서 없음」을 밝힌 뒤 초안 모드로 간다.

## 2. 초안

- 일곱 칸을 채운다. 근거가 없는 줄은 「(가설)」과 무엇을 보면 확정하거나 버릴지 붙인다.
- 원칙은 「A와 B가 갈리면 A, 잃는 것은 …」 꼴로 쓴다.
- 성공 기준은 사용자의 행동·경험 변화로 쓴다. 기준값을 모르면 「기준값을 잰 뒤 정함」.
- 사용자가 말하지 않은 사용자·수치·원칙을 만들지 않는다.

## 3. 판정

- 대상을 「누가·어떤 상황에서·무슨 문제」로 다시 쓴다.
- 대상 사용자·핵심 문제·원칙·비목표와 대조해 **진행·보류·방향 변경** 중 하나를 권장한다. 근거로 `PRODUCT.md`의 문장을 인용한다.
- 「(가설)」·「미정」 줄에 걸리면 그 줄을 먼저 정해야 한다고 알린다. 정하지 않고 진행하려면 사람의 승인과 되돌릴 범위를 PRD Rationale에 남긴다.
- 사람이 고르기 전에는 파일을 만들거나 고치지 않는다.

## 4. 점검

1. 핵심 기능과 진행 중 작업을 목록으로 만든다(화면·README·이슈·PRD 목록).
2. 기능마다 방향과 대조해 유지·개선·보류·제거 후보와 불일치 근거를 적는다.
3. 제거 후보는 지금 사용자와 연결된 흐름·데이터에 미치는 영향을 확인해 적는다.
4. 후보가 하나라도 있으면 `docs/decisions/YYYY-MM-DD_방향-점검.md`에 표로 남긴다. 결정은 사람이 하고, 결정된 것만 해당 PRD와 이슈로 옮긴다.

## 5. 변경

1. 근거를 확인한다. 대상 사용자·핵심 문제·가치가 틀렸다는 관찰이 쌓였거나, 기존 방향을 유지할 수 없는 제약이 확인됐는가. 성과가 낮다는 사실만으로는 바꾸지 않는다. 원인이 구현·사용성·해결책 쪽일 수 있으면 그 판정을 먼저 받는다.
2. 근거가 부족하면 필요한 증거와 확인 방법을 적고 멈춘다.
3. 사람이 바꾸기로 하면 `PRODUCT.md`를 고치고, 끝에 변경 이유·관찰 근거·영향받는 기능을 날짜와 함께 남긴다.
4. 전파표의 방향 행대로 영향받는 PRD·디자인·계약·테스트 목록을 보고에 낸다.

## 6. 검사

`PRODUCT.md`를 고쳤으면 돌린다.

```bash
python3 <이 플러그인>/scripts/check_d3_docs.py --root <프로젝트>
```
