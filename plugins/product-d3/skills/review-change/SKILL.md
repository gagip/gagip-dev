# review-change

변경 자체와 요청만으로 판정하고, 만든 쪽의 설명은 대조할 주장으로만 쓴다. 기준은
[verification-system.md](../../references/verification-system.md), [change-propagation.md](../../references/change-propagation.md),
[work-contract.md](../../references/work-contract.md)다. 이 스킬은 파일과 git 상태를 바꾸지 않는다.

## 1. 입력 묶음

| 항목 | 찾는 곳 |
|---|---|
| 대상 레포 절대경로, base, HEAD | `git merge-base HEAD <기준 브랜치>` 또는 PR의 base. `git rev-parse HEAD` |
| 변경 파일 | `git diff <base>...HEAD --name-only`, `git diff HEAD --name-only`, `git ls-files --others --exclude-standard` |
| 요청 원문 | 사용자 말, 이슈, PR 본문의 목표 |
| 작업 정의·완료 조건 | 계획서·이슈·PR 본문. 없으면 「완료 조건 없음」으로 적는다 |
| 관련 PRD | 변경 파일과 PRD References로 찾는다 |
| 보고된 검증 | PR 본문·보고의 「돌린 검사와 결과」, 검증 기록 폴더 |

구현 대화·설계 이유·이전 판단은 넣지 않는다.

## 2. 범위 검사

```bash
python3 <이 플러그인>/scripts/scope_check.py --base <base> --root <레포> [--allow '<요청 범위 glob>']
```

걸린 항목(범위 밖 파일, 테스트 삭제·skip·단언 감소, 새 의존성)은 그대로 3절 검토자에게 넘기고 판정에도 싣는다.
PRD·`PRODUCT.md`가 바뀌었으면 `check_d3_docs.py --root <프로젝트>`도 돌린다.

## 3. 독립 검토

[code-review-criteria.md](../deliver-work/references/code-review-criteria.md)의 관점(정확성·계약, 가독성·명확성, 최소 변경,
테스트, 조건부 사용자 노출 문구)마다 읽기 전용 서브에이전트를 한 응답에서 병렬로 띄운다. 같은 응답에서 D3 점검
서브에이전트를 하나 더 띄워 아래 항목마다 통과·지적·미확인을 받는다.

1. 요청과 완료 조건을 모두 충족하는가
2. 요청 범위 밖 변경이 있는가
3. 테스트 삭제·비활성화·기대값 완화로 실패를 숨겼는가
4. 지킬 기존 동작이 보존되는가(그 동작을 보는 테스트가 있는가)
5. 바뀐 의도의 원본(PRD·계약·테스트)을 고쳤고, 전파표의 영향받는 곳을 빠뜨리지 않았는가. 요구가 그대로인 버그 수정·
   리팩터링이 PRD를 고쳤으면 지적한다
6. 코드·테스트로 드러난 동작을 문서에 다시 적었는가, 상충하는 옛 요구가 남았는가
7. 보고된 검증이 실제로 실행된 것인가(기록·출력과 대조). 못 한 검사가 「미검증」으로 표시됐는가

지시서 형식·제약·보고 형식은 code-review-criteria.md 3절을 따른다. 서브에이전트를 쓸 수 없으면 같은 관점으로 직접 보고
판정 첫 줄에 「독립 검수 미실행」을 밝힌다.

## 4. 판정

code-review-criteria.md 4절대로 보고를 대조한다. 보고가 밝힌 HEAD가 다르면 버리고 다시 띄운다. 결함 후보(code-review-criteria.md의 🔴)는 코드를 직접
다시 읽어 확인한다. 결과를 셋으로 나눠 대화에 낸다.

| 분류 | 담는 것 |
|---|---|
| 결함 | 결함으로 확인된 지적. `파일:줄`, 문제, 수정안 |
| 요청에 없는 변경 | 범위 밖 파일·기능, 빼도 요청이 지켜지는 이유 |
| 미확인 | 실행해야 알 수 있는 것, 증거가 없는 검증 주장 |

D3 점검 7항목의 통과·지적·미확인을 표 한 장으로 붙인다. 범위를 넓혀야 고칠 수 있는 지적은 사람이 정할 목록으로 따로
적는다. 그 밖의 지적(🟡)은 한 줄씩 「발견했으나 결함 아님」으로 남긴다. 지적 반영은 구현(`deliver-work`)이 맡는다.
