# observe-outcome

완료는 「제대로 만들었나」, 성과는 「만들 가치가 있었나」다. 이 스킬은 성과를 본다. 기준은
[verification-system.md](../../references/verification-system.md)의 성과 조건, 원인 분기는
[change-propagation.md](../../references/change-propagation.md), 경로는 [paths-and-templates.md](../../references/paths-and-templates.md)를 따른다.

## 1. 성과 조건 읽기

PRD의 Success Criteria에서 대상 사용자, 관찰 항목, 성공으로 볼 결과, 표본·기간, 볼 날을 찾는다. 조건이 없거나
「기준값을 잰 뒤 정함」이면 결과를 본 뒤 기준을 지어내지 않는다. 판단 유보로 두고, 지금 잴 수 있는 기준값과 다음에 볼
날을 제안한다.

## 2. 관찰 모으기

- 사용 기록·지표·피드백·버그 보고·인터뷰에서 성과 조건의 관찰 항목을 찾는다. 출처와 시점을 붙인다.
- 관찰을 `RESEARCH.md`(기능 폴더 안, 없으면 만듦)에 날짜 항목으로 더한다. 옛 관찰을 지금 사실로 고쳐 쓰지 않는다.
- 에이전트가 만든 분석·요약은 실제 사용자 증거가 아니라고 표시한다.
- 표본·기간이 조건에 못 미치면 판정을 유보하고 모자란 증거와 모을 방법을 적는다.

## 3. 원인 분류

문제나 새 근거를 이 순서로 묻고 처음 「아니오」가 나온 곳에서 멈춘다.

| 질문 | 아니오면 | 다음을 맡는 곳 |
|---|---|---|
| 의도된 동작대로 작동하나 | 구현·계약 결함 | Bug Fix(`deliver-work`) |
| 사용자가 쓸 수 있고 해결책이 효과적인가 | 사용성·해결책 문제 | Enhancement(`deliver-work`) 또는 해결책 재탐색(`discover-problem`) |
| 문제·사용자 가설이 맞나 | 문제 가설 실패 | `discover-problem` |
| 방향을 유지할 수 있나 | 방향 근거 | `set-direction` |

- 근거가 부족해 어느 칸인지 가를 수 없으면 조사·검증을 먼저 제안한다.
- 성과가 낮다는 사실만으로 방향 변경을 권하지 않는다. 앞 세 칸을 근거로 배제한 뒤에만 방향 칸으로 간다.

## 4. 판정과 반영

- 유지 · 개선 · 제거 · 판단 유보 중 하나를 권장하고, 근거로 성과 조건과 관찰 항목을 나란히 보인다. 고르는 것은 사람이다.
- 사람이 고른 뒤 PRD의 Success Criteria·Rationale 중 바뀐 것만 고친다. 제거면 PRD 첫머리에 날짜와 이유를 적는다.

```bash
python3 <이 플러그인>/scripts/check_d3_docs.py --root <프로젝트>
```
