## Product D3

- 제품 판단 기준: `PRODUCT.md`
- 기능 요구사항: `docs/features/<feature>/PRD.md`
- 읽는 순서: 이 파일 → `PRODUCT.md` → 관련 PRD → 계약·코드·테스트 → 필요할 때 의존성과 외부 자료
- 동작 규칙은 읽기 쉬운 코드·타입·계약·테스트에 둔다. 코드에서 확인할 수 있는 동작을 문서에 다시 적지 않는다.
- 기대 동작을 임의로 바꿔 테스트를 통과시키지 않는다. 요구사항이 바뀌면 PRD·계약·테스트를 함께 고친다.
- 요구사항과 구현이 어긋나면 임의로 해석하지 않고 의도를 확인한다.
- 제품 의도 변경, 범위 확대, 데이터 손실·개인정보·안전 위험, 기준 충돌, 진행 불가면 문제와 대안을 보이고 판단을 요청한다.
- 완료 보고: 바꾼 것 · 실제로 돌린 검증과 결과 · 미검증과 남은 문제
- 검증 명령: {verify_command}
