# 계획 모드 도구가 없을 때의 절차

이 절차는 현재 턴에 계획 모드 진입 또는 이탈 도구가 제공되지 않을 때만 사용한다. 도구가 있으면
`SKILL.md`의 기본 경로를 그대로 따른다.

## 1. 현재 모드 존중

사용자가 이미 하네스의 계획 모드로 시작했다면 그 모드의 읽기 전용·출력 형식 제약을 따른다.
모델이 직접 모드에 진입할 수 없으면 진입한 척하지 않는다. 계획 모드가 아니어도 조사와 계획서
작성은 계속할 수 있다.

## 2. 완결 계획서 파일을 먼저 보존

`SKILL.md`의 5절 PRD 골격으로 완결 계획서를 파일에 저장한다. 저장 위치 우선순위:

1. 현재 하네스가 지정한 계획 파일
2. 프로젝트 지침 파일에 적힌 계획 저장 관례
3. 기존 `.private/` 또는 `private/` 아래 `plans/<topic-slug>.md`
4. 위 디렉터리가 하나도 없으면 `.private/plans/<topic-slug>.md`

하네스가 대화의 계획 답변을 3~5개 단계처럼 짧게 제한하더라도 파일의 5절 골격을 줄이지 않는다.
대화에는 파일 계획을 요약한 짧은 단계만 내고, 전체 배경/문제 정의·목표/비목표·요구사항·성공
지표·리스크는 파일에 보존한다. 계획 모드 종료가 새 컨텍스트로 이어지는 하네스에서는 이 파일이
유일한 인계 매체이므로 저장을 생략하지 않는다.

## 3. 승인 관문

계획 모드 이탈 도구가 없으면 구조화 질문 도구로 "이 계획대로 구현할지 / 계획을 수정할지"를
묻는다. 구조화 질문 도구도 없으면 같은 두 선택을 대화에서 명시적으로 묻는다.

- 같은 컨텍스트에서 계속할 수 있고 사용자가 승인하면 바로 구현한다.
- 하네스가 계획 승인 뒤 새 컨텍스트로 넘기는 방식이면 구현을 시작하지 않는다. 저장한 계획 파일
  경로와 다음 컨텍스트에서 실행할 짧은 인계 문구를 남긴다.
- 사용자가 이미 "계획 후 진행"까지 명시했고 현재 하네스 규칙이 별도 승인을 요구하지 않으면,
  계획 파일 저장 뒤 구현을 계속한다.

## 4. 진행 추적

계획서 자체에는 진행 추적 장치를 두지 않는다. 하네스에 작업 추적 도구(Task 목록 등)가 있으면
그걸로 구현 단계를 추적하고, 없으면 커밋 단위와 대화의 짧은 체크리스트로 충분하다.
