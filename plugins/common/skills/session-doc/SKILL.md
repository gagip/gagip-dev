# 세션 문서

세션 문서는 사용자와 세션이 목표·진행 상태·결정을 주고받는 화면이다. 사용자는 대화창 대신 이 한 장으로
지금 상태와 남은 결정을 보고, 에이전트는 컨텍스트 압축 뒤 이 한 장으로 하던 일을 되찾는다.
서브에이전트·읽기 전용 지시엔 만들지 않는다.

## 만들기

위치는 프로젝트 지침이 정한 세션 문서 경로를 따른다. 정한 곳이 없으면 사용자에게 묻는다. 파일 이름
`YYYY-MM-DD_<세션 목적>.html`.

```bash
python3 <이 스킬>/scripts/session_doc.py new <경로.html> --title "<세션 목적>"
```

뼈대(디자인 시스템 CSS, 고정 칸 세 개)가 생긴다. 이어 쓰는 세션은 기존 문서를 연다. 예전 `.md`
세션 문서는 그대로 이어 쓴다.

## 칸

제목과 지금 상태 바로 다음에 이번에 사람이 판단할 내용이 있으면 `<section id="decision">` 하나를 둔다.
그 아래 `<details id="context">`에 명세와 진행을 묶어 접는다. 판단할 내용이 없으면 `#decision` 없이
`#context`를 펼쳐 둔다. 기존 HTML을 이어 쓸 때도 다음 검토를 준비하며 이 배치를 적용한다.
고정 칸 `#state` → `#spec` → `#flow`의 id와 상대 순서를 유지한다.

- 작업 전에는 **지금 고를 것**을 앞에 둔다. 선택지의 결과 차이, 시안이나 조작할 실험 링크, 성공 기준과 멈출 조건을 판단에 필요한 만큼 보여준다.
- 작업 후에는 **지금 검토할 것**을 앞에 둔다. 변경 전후와 핵심 성공 기준별 실행 결과를 연결하고, 미검증과 남은 판단을 드러낸다. PR이 있으면 PR과 원본 실행 기록으로 바로 갈 수 있게 한다.

| 칸 | 담을 것 |
|---|---|
| 지금 상태 `#state` | 상태 표시 하나(`pill run` 진행 중 · `wait` 사용자 답 기다림 · `stop` 막힘 · `ok` 끝)와 한 문장. 지금 하는 작업, 다음에 할 일 |
| 명세 `#spec` | 목표 · 완료 기준(기준마다 증거 종류 하나) · 제약사항 · 비목표 · 검증 수단 · 결과물(절대경로)을 한 줄씩. 착수 전에 채우고 `grill`이 닫을 때 확정한다 |
| 진행 `#flow` | 핵심 작업 흐름의 단계 이름 한 줄. `li.ok` 완료 · `now` 지금 · `wait` 대기 · 표시 없음 남음. 하네스 작업 목록과 같은 단계로 둔다 |

그 아래는 세션 내용에 맞게 짠다. 부품과 쓰는 HTML은 [assets/sample.html](assets/sample.html) 견본에 있다.
흔히 쓰는 칸:

- 사용자가 정할 것: 번호 목록 `ol.ask`. 한 줄에 질문 · 「권장: 안」(`.rec`) · 다른 안, 이유나 반론은 `.why` 한 줄. 없으면 칸을 만들지 않는다
- 정한 것: 표 한 장(질문 · 고른 안 · 근거로 사용자 답 원문), 접힌 「합의와 달라진 점」
- 한 일: 표 한 장(대상 · 문제(실제 값) · 바꾼 것(파일과 무엇) · 확인(명령·캡처와 결과, 못 했으면 "미검증")). 코드 발췌처럼 칸에 안 들어가는 것만 `h3` + `dl.rows`
- 남은 일: 목록과 이슈 링크
- 시안·그래프·전후 비교: `.compare`, `table`, `figure`

새 모양이 필요하면 목록·표를 조합하거나 그 칸에 `style` 속성으로 덧붙이고, 여러 세션에서 반복되면
`assets/ui.css`와 견본에 부품을 더한다.

## 지킬 것

- 상자(테두리·배경)는 `#decision`·`#spec`·`figure`·`.compare`와 위험 한 줄 `.note`에만, 둥근 표시는 `#state` 상태 표시
  하나에만 쓴다. 나머지는 `h2` 아래 목록·표·문단으로 둔다. 항목마다 상자나 칩을 씌우면 화면이 카드로 가득 차
  훑어보기 어렵다. 옛 부품 class(`q`·`op`·`item`·`grid`·`decided`)는 `check`가 실패시킨다. 옛 문서를 이어
  쓰다 걸리면 그 칸을 위 목록·표로 바꾼다.
- 사용자가 훑어보고 바로 이해하게 쓴다. 상태·흐름·화면·비교는 글 대신 `figure`(인라인 SVG)·`table`·`.compare`로
  보이고, 글은 칸마다 한두 문장으로 줄인다. 원문 발췌·조사 근거·긴 목록은 같은 폴더의 md 파일에 두고
  세션 문서에는 그 절대경로만 적는다. 세션 문서가 길어질수록 사용자가 지금 상태와 남은 결정을 놓친다.
- 스크립트를 넣지 않는다. 앱 옆 창은 작업 폴더 밖 파일을 스크립트 없이 정적으로 띄워 탭·버튼이 동작하지
  않는다. 조작해 볼 시안·실험은 같은 폴더에 따로 HTML을 만들고, 판단할 내용 옆에서 열 수 있게 링크한다.
  실험에서 고른 값이 구현 조건이 되면, 선택한 규칙·예상 결과·값을 복사 가능한 텍스트로 제공한다.
- CSS는 손으로 고치지 않는다. `<style id="ui">`는 스크립트가 `assets/ui.css`로 덮어쓴다.
- 다른 사람이 읽을 결론 보고는 프로젝트가 정한 작업 보고 위치에 따로 두고, 세션 문서에는 그 경로만 적는다.

## 갱신과 띄우기

갱신 시점: 작업 하나를 끝냈을 때, 사용자에게 묻기 직전, 보고 직전. 고친 뒤 정확히 이 명령을 실행한다.

```bash
python3 <이 스킬>/scripts/session_doc.py sync <경로.html>
```

CSS를 최신으로 바꾸고 갱신 시각을 지금으로 맞춘 뒤 고정 칸·스크립트를 검사한다. `실패`가 나오면 고치고
다시 돌린다. 통과하면 파일 보내기 도구(`display: render`)로 옆 창에 다시 띄운다. 파일 보내기 도구가 없는
하네스에선 경로를 대화에 적는다.

사용자가 검토하는 문서(계획서·명세·지침·스킬)를 고쳤으면 바뀐 줄을 GitHub 차이 보기처럼 그린 이미지(앞뒤 그대로인 줄 포함)를 만들어 대화에 올린다.
기준은 git `HEAD`(기본) 또는 `--base-file <고치기 전 사본>`이다. 20줄을 넘으면 절별로 나눈 나머지 장 경로도 출력된다.

```bash
python3 <이 스킬>/scripts/doc_change_image.py <문서> [--base-file <사본>] --out <결과.png>
```

사용자가 고를 것이 생기면 `#decision`의 「지금 고를 것」을 채우고, 대화창에도 선택지 버튼(누르면 채팅으로 답이
들어오는 위젯이나 하네스의 질문 상자)을 띄운다. 받은 답은 그 질문을 `ol.ask`에서 빼 「정한 것」 표에 한 행으로 옮기고, 근거 칸에 답 원문을 적는다.

## 끝 보고

따로 보고서를 만들지 않는다. 검토가 필요하면 `#state`를 `wait`로 두고 `#decision`에 변경 전후와 핵심 증거를 보여준다.
판단까지 끝나면 `#state`를 `ok`로 바꾸고 「한 일」과 「남은 일」을 갱신해 `sync` 뒤 띄운다. 대화창에는 5줄 안팎 개요와 세션
문서 경로만 쓴다. 짧은 답·파일 하나 수정은 세션 문서 없이 글로 보고한다.
