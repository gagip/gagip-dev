# 일 맡기기

하위 세션(이 세션이 새로 띄운 세션)은 사용자가 직접 열어 대화하는 별도 세션이고, 서브에이전트는 이 세션이 결과만 돌려받는 일꾼이다.
여기서 정하는 것은 누가 하느냐와 결과를 어떻게 확인하느냐다.

## 1. 고르기

나눌 일마다 위에서부터 처음 맞는 줄을 쓴다. 사용자가 이 세션에 맡긴 일 하나는 PR을 내더라도 이 세션이 한다.

| 조건 | 방식 |
|---|---|
| 사용자가 방식을 정해 말했다 | 그 방식. 다른 쪽이 나아 보이면 이유를 한 줄로 알리고 그대로 진행한다 |
| 도구 몇 번이면 끝난다 | 직접 |
| 도중에 사용자와 대화해 정해야 한다, 별도 브랜치·PR로 나간다, 하루를 넘긴다 | 하위 세션 |
| 그 밖의 조사·점검·독립 검토(결과를 받아야 지금 일이 이어진다) | 서브에이전트 |

한 변경의 조각은 크더라도 하위 세션으로 나누지 않는다. 조각마다 브랜치를 합치고 창을 확인하는 일이 사용자에게 돌아간다.

## 2. 맡기기

지시문만 읽고 일할 수 있게 쓴다.

- 목표와 완료 기준(기준마다 증거)
- 고칠 파일과 건드리지 않을 것
- 쓸 기기·서버·계정. 없으면 「없음」
- 하위 세션이면: 사용자가 그 하위 세션 창에서 직접 승인할 일(외부 게시, 콘솔 설정 변경, 파일 내려받기처럼 되돌리기 어려운 것).
  다른 세션이 전달한 승인으로는 진행하지 않는다고 적는다
- 보고에 담을 것: 결과, 증거 위치, 미검증, 남은 일, 브랜치·PR

같은 파일이나 같은 기기를 쓰는 일은 동시에 띄우지 않고 차례로 돌린다. 띄우기 전에 사용자가 직접 승인할 일을
한 줄로 알린다.

## 3. 받기

하위 세션의 알림을 받았을 때:

- 알림은 보고 앞부분만 담는다. 완료 보고면 전문을 읽고, 거기 적힌 파일·PR·실행 결과를 하나 이상 직접 확인한 뒤 완료라고 말한다. 확인하지 못했으면 「보고 기준, 미확인」이라고 쓴다.
- 진행 알림은 한 줄로 전하고, 사용자가 답할 것이 있으면 따로 표시한다.
- 사용자의 결정은 그 결정을 쓰는 세션에 원문 그대로 보낸다. 2단계에서 사용자가 직접 승인하기로 한 일은 전달로 대신하지 않고, 어느 세션에서 승인하면 되는지 알린다.
- 진척과 결정 대기는 이미 쓰는 세션 문서나 체크리스트에 적는다. 새 작업판을 만들지 않는다.

## 4. 닫기

세션마다 차례로 본다.

1. 완료 보고 전문과 거기 적힌 파일·PR을 확인한다.
2. 커밋 안 한 변경, 합치지 않은 브랜치, 열린 PR이 남았으면 누가 이어받는지 정한다. 정해지지 않았으면 닫을 세션에 넣지 않는다.
3. 남은 일을 프로젝트가 정한 곳이나 이슈에 적는다. 세션 대화에만 있는 일은 닫으면 찾기 어렵다. 사용자가 닫아도 되는지 묻기만 했으면 적을 내용을 보이기만 하고, 이슈를 만드는 데 승인이 필요한 레포면 먼저 승인받는다.
4. 닫을 세션과 남길 세션을 이유와 함께 보이고, 사용자가 닫으라고 한 것만 보관한다. 보관 도구가 없으면 닫을 세션 이름을 건넨다.

## 도구가 없을 때

하위 세션 도구가 없으면 서브에이전트에 맡기거나 직접 하고, 하위 세션으로 하지 못한 부분을 밝힌다. 서브에이전트
위임도 불가능하면 직접 하고, 독립 검토였다면 「독립 검증 미실행」을 밝힌다.
