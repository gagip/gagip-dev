# 작업 구현

이 플러그인의 진입 스킬은 하나다. 상태·순서는 `cycle.py`, 단계 검증은 `gate.py`,
실제 구현 방법은 대상 레포의 `CLAUDE.md`/`AGENTS.md`가 담당한다.
`handoff.md`는 상태 기록이며 실행 권한의 증거가 아니다.

## 실행 위치와 작업 접수

스크립트는 이 스킬 디렉터리의 `scripts/`에 있다. 아래 명령의 `scripts/cycle.py`는 이 스킬
디렉터리 기준 경로다.

- 기존 사이클은 `cycles/<주제>/handoff.md`를 찾아 이어간다.
- 새 작업은 `cycles/_TEMPLATE/`를 복사하고 식별 정보·작업 제목을 채운다.
  `repo`·`branch`·`base`·`allow_main`은 branch 단계에서 실제 작업 위치에 맞춰 채운다.
- 같은 이슈의 기존 사이클·브랜치가 발견되면 중복 생성하지 않고 사용자에게 확인한다.
  대상 레포에서 `git worktree list`와 `git branch --list`로 확인한다.

새 작업을 접수하거나 새 세션에서 기존 작업을 이어갈 때는
프로젝트 지침이 정한 맥락 수집 절차가 있으면 그것으로 필요한 맥락만 선별 수집한다.

- 기본 요청: **구현 상태** + 작업 목적·대상 레포·이슈/PR 번호
- 현재 진척을 여러 시스템과 대조해야 할 때만: **작업 진척**
- API 경로·인증·요청·응답이 바뀔 때만: **API 계약**
- 제품 방향이나 과거 합의가 구현 선택을 가를 때만: **제품 방향**, **과거 결정의 이유** 또는
  **현재 결정의 근거**

컨텍스트 팩 전체를 사이클 산출물에 복사하지 않는다. 범위·검증 조건을 바꾸는 사실과 충돌만
`00_intake.md`에 자족적으로 반영한다. 수집기를 사용할 수 없으면 확인하지 못한 출처와 영향을
알리고, 로컬 코드·GitHub 등 접근 가능한 근거만으로 범위를 한정한다.

## 상태 머신으로 실행

### 1. 조회한다

```bash
python3 plugin/scripts/cycle.py <사이클 폴더> status
```

명령은 진행 순서와 완료된 단계의 실제 상태를 다시 검사한다. 현재 단계가 ship·close이면
커밋 작성자·메시지·미커밋 변경도 검사한다. 실패하면 원인을 고친 뒤
재조회한다. 실패 출력이 있는데 다음 단계로 진행하지 않는다. 종결 상태면 실행을 끝낸다.
`gate.py --stage`는 개별 관문의 읽기 전용 진단일 뿐, 단계 완료나 다음 단계 실행 승인이 아니다.

### 2. 현재 단계의 절차만 읽고 수행한다

| 현재 단계 | 읽을 절차 |
|---|---|
| intake | [작업 접수](references/intake.md) |
| branch·implement·simplify·review·docs·ship | [실행 절차](references/execution.md)의 공통 원칙과 해당 단계 절 |
| close | 아래 종결 절차 |

커밋은 별도 단계가 아니다. 구현·정리·리뷰 수정·문서 작업에서 작은 변경마다 검증하고 커밋한다.
산출물은 기존 파일명을 유지한다: `00_intake.md` · `01_branch.md` · `02_implement.md` ·
`03_simplify.md` · `04_review.md` · `05_docs.md` · `07_ship.md` · `08_close.md`.
새 `06_commit.md`는 만들지 않고 해당 작업 산출물에 커밋을 기록한다.

### 3. 검증 후 완료를 기록한다

산출물을 작성한 뒤 다음 명령을 실행한다. 진행 표·종결값·결정 로그를 먼저 완료로 고치지 않는다.

```bash
python3 plugin/scripts/cycle.py <사이클 폴더> complete intake --artifact 00_intake.md --decision "작업 범위와 검증 조건을 코드와 대조해 확정"
```

단계와 산출물을 현재 작업에 맞춰 바꾸고, `--decision`에는 무엇을·왜·누가 정했는지 한 줄을 적는다.
명령은 현재 미완 단계만 받아 선행 관문과 현재 관문을 확인하고, 성공한 경우에만 상태와 로그를
함께 저장한다. 실패하면 파일을 바꾸지 않는다. 완료 뒤에는 1번으로 돌아가 다음 단계를 수행한다.

CLI끼리의 동시 저장은 잠금으로 막고 검사 중 외부 파일 변경도 확인한다. 잠금을 따르지 않는
편집기의 저장까지 완전히 막는 것은 아니므로, 같은 사이클을 동시에 수동 편집하지 않는다.

## 제출 모드

기본은 초안(`draft`)이다. 기존 파일에 `mode`가 없어도 초안으로 읽는다. 사용자가 리터럴
`--auto`를 명시한 경우에만 다음 명령으로 자동 모드를 기록한다. 자연어 "자동으로 해줘"는
자동 모드 요청으로 해석하지 않는다. 상태 파일의 auto 값이 사용자 승인이나 도구 권한을 대신하지 않는다.

```bash
python3 plugin/scripts/cycle.py <사이클 폴더> mode auto --decision "사용자가 --auto로 push·PR까지 요청"
```

사용자가 제출을 원하지 않으면 ship 처리 전에 `mode draft`로 되돌린다. 이미 처리한 ship을
모드 변경으로 되살리지 않는다. PR 머지는 이 절차가 하지 않는다.

초안의 현재 단계가 ship이면 push·PR을 수행하지 않고 다음과 같이 기록한 뒤 close로 간다.
앞 단계가 미완이거나 커밋 검사에 실패하면 생략할 수 없고, 다른 단계는 생략할 수 없다.

```bash
python3 plugin/scripts/cycle.py <사이클 폴더> skip ship --decision "초안 모드이므로 원격 제출 생략"
```

## 종결과 중단

close에서는 intake의 검증 조건 각각에 대한 결과와 `달성`을 `08_close.md`의 `## 종결`에 적는다.
`complete close --artifact 08_close.md --decision "검증 조건 충족으로 종결"`을 실행하면 마지막 단계
완료와 전체 종결값을 함께 검사·저장한다. 검증 조건을 충족하지 못했으면 달성으로 닫지 않는다.

입력이 실제 코드와 어긋나거나 필요한 도구·권한이 없거나 같은 실패가 반복되어 판단이 필요하면
사용자에게 근거를 보여주고 멈춘다. 단순 승인 대기·작업 보류는 진행중 상태를 유지한다.
사용자가 작업이 불가능하다고 판단한 경우에만 다음 명령으로 그 근거를 기록한다.

```bash
python3 plugin/scripts/cycle.py <사이클 폴더> stop --decision "사용자가 판단한 불가능 사유"
```

stop은 선행 관문 실패와 무관하게 종결할 수 있지만, 미완 단계를 완료·생략으로 바꾸지 않는다.
종결된 사이클의 변경 명령은 거절된다. 최종 보고에는 작업 위치·검증 결과·종결값·미반영 리뷰 지적·
문서 영향과 커밋·제출 여부를 알린다.
