# work-plan 검수 기준

계획서를 쓴 맥락을 모르는 상태에서 사용자 요청 원문과 계획서만 읽고 채점한다. 절이 있는지는 코드가 이미 검사하므로
여기서는 내용만 본다. 항목마다 통과·미통과와 계획서 인용을 답한다.

## 항목

| # | 기준 | 통과 조건 |
|---|---|---|
| 1 | 착수할 사람이 언제 끝났다고 할지 아는가 | 완료 기준이 돌릴 명령·확인할 결과·남을 파일처럼 관찰할 수 있는 말로 적혀 있다 |
| 2 | 현재 상태가 확인한 사실에 기대는가 | 사실마다 출처(경로·줄·커밋)나 "미확인"이 붙어 있고, 요청에 없던 일정·수치를 지어내지 않았다 |
| 3 | 요청 범위를 지켰는가 | 요청에 없는 작업이 방안에 없고, 하지 않는 것이 범위 밖에 적혀 있다 |
| 4 | 정할 것을 계획서만 읽고 답할 수 있는가 | 사안마다 배경·선택지·권장안이 있고, 번호·파일명·내부 약어로만 부르지 않는다. 정할 것이 없으면 "없음"이 맞다 |
| 5 | 검증 수단이 결함을 잡는가 | 무엇을 돌려 무엇을 보는지, 새 테스트가 어떤 결함을 잡는지가 이 작업에 맞게 구체적이다 |
| 6 | 멈춤 전제가 쓸모 있는가 | 틀리면 작업 상당 부분이 헛수고가 되는 전제만 있고, 깨졌다고 볼 관찰이 구체적이다. 없으면 "없음"이 맞다 |
| 7 | 짧은가 | 진행 상황·작업 경위·되풀이가 없고 1~2쪽 안이다 |

## 답 형식

```
#<번호> 통과 | 미통과
근거: "<계획서에서 인용한 문장>"
고칠 문장: <미통과일 때>
```
