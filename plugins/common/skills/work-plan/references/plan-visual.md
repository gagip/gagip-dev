# 계획 시각 자료

승인할 사람이 글을 읽지 않고도 "무엇이 어떻게 바뀌고, 무엇을 골라야 하는지"를 눈으로 보고 정하게 하는 HTML 한 장이다. 계획서(md)는 그대로 두고, 이 파일은 계획서 옆에 둔다.

## 언제 만드나

- 화면·문구·사용자에게 보이는 동작이 바뀐다
- 정할 것이 있고, 선택지마다 결과가 눈에 보이게 달라진다(화면, 숫자, 흐름)
- 사용자가 요청했다

내부 리팩터·한 줄 수정처럼 보여 줄 결과가 없으면 만들지 않는다.

## 구성 — 위에서 아래로

1. 머리: 무엇을 하는 계획인지 2~3문장. 예시 데이터를 쓰면 무엇을 가정했는지(오늘 날짜, 처음 측정한 날 등) 함께 적는다.
2. 바뀌는 것마다 한 칸. 지금 모습(실기기 캡처·현재 코드 출력)을 왼쪽에, 바뀐 모습을 오른쪽에 둔다. 그다음 상황별 변형(처음, 끊김, 빈 상태, 큰 글자, 좁은 폭, 어두운 테마 중 해당하는 것)을 나란히 둔다. 그림마다 캡션 한 줄과 "무엇이 달라졌는지" 보조 한 줄을 단다.
3. 정할 것마다 한 칸. 같은 예시 데이터로 선택지별 결과를 나란히 그리거나 표로 비교한다(예: "A로 세면 53일, B로 세면 52일"). 권장안에 표시를 달고 장단점을 한 줄씩 적는다.
4. 이번에 하지 않는 것. 흐리게 처리하고 뺀 이유를 한 줄로 쓴다.
5. 데이터 출처·작업 단위(PR 나눔 등)는 짧은 표나 상자로 둔다.

## 만드는 법

- 새로 생기는 부분은 점선 테두리처럼 눈에 띄게 표시하고, 위쪽에 이 표시를 켜고 끄는 토글을 둔다.
- 화면은 그림을 따로 그리지 않는다. 디자인 시안·앱의 실제 부품 스타일과 계산 로직을 가져와 예시 데이터로 실제로 계산해 그린다. 그래야 숫자와 규칙이 계획과 어긋나지 않는다.
- 움직임이 있으면 재생하고, "다시 보기" 단추를 둔다.
- 지금 화면 캡처는 base64로 넣어 HTML 한 파일로 열리게 한다. 지금 화면을 구하지 못했으면 그 칸에 "지금 화면 캡처 없음"이라고 적는다.
- 문구는 계획서에 적은 원문과 같게 쓴다.
- 쉬운 한국어로 쓴다. 섹션 번호 대신 무엇을 정하는지로 부른다.

## 확인과 전달

- 브라우저로 열어 각 칸을 스크린샷으로 확인한다(깨짐, 이미지 누락, 계산 결과).
- 계획서 머리에 이 파일 경로를 한 줄로 적는다.
- 파일 보내기 도구로 대화에 렌더해 띄우고(`display: render`), 대화에는 무엇을 담았는지와 정할 것만 짧게 적는다.
