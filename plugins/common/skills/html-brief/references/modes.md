# 문서 모드와 구조화 데이터

필수 골격만 유지하고, 내용이 없는 절은 만들지 않는다. 섹션 이름은 독자에게 자연스러운 문구로 바꿀 수 있다.

## 의사결정 모드

독자가 승인·선택·제외 범위를 정해야 할 때 사용한다.

권장 순서:

1. **첫 화면** — 제목, 기준일, 수신자, 결정해야 할 한 문장
2. **확정 사항 / 남은 결정** — 이미 정한 것과 이번에 정할 것을 분리
3. **핵심 제약** — 선택지를 실제로 가르는 사실 1~3개
4. **권고안** — 무엇을 선택하는지와 판단 기준
5. **비교** — 선택지 또는 항목별 효과·비용·위험·제약
6. **결정 요청** — 승인하거나 제외할 범위를 수신자가 바로 표시할 수 있게 서술
7. **결정 후 영향** — 다음 작업, 정책·비용·일정 영향
8. **출처와 한계** — 원문 URL, 확인일, 미확인 사항

선택지가 실질적으로 하나뿐이면 억지로 복수안을 만들지 않는다. “대안 없음”과 이유를 적는다.

## 보고 모드

독자가 조사·검토·작업 결과를 이해하고 후속 작업에 사용할 때 적용한다.

권장 순서:

1. **첫 화면** — 제목, 기준일, 수신자, 한 문장 결론
2. **요약** — 가장 중요한 결과 3개 이내
3. **근거 또는 발견 사항** — 결론을 바꾸는 사실 중심
4. **영향과 위험** — 현재 작업·제품·개인 프로젝트에 미치는 의미
5. **후속 작업** — 해야 할 일, 순서, 보류 조건
6. **한계와 미확인 사항** — 이번 보고가 답하지 못한 범위
7. **출처** — 원문 URL과 확인일

작업 일지처럼 시간순으로 나열하지 않는다. 시간 순서 자체가 결론을 설명할 때만 타임라인을 쓴다.

## `brief-data` JSON

HTML 하단에 아래 형태의 JSON을 포함한다. 독자에게 보이는 본문과 내용이 어긋나지 않아야 한다.

```html
<script id="brief-data" type="application/json">
{
  "document": "문서 제목",
  "mode": "decision",
  "asOf": "YYYY-MM-DD",
  "audience": ["수신자"],
  "summary": "한 문장 결론",
  "sources": {
    "S1": {
      "title": "원문 제목",
      "url": "https://example.com/source",
      "checkedAt": "YYYY-MM-DD"
    }
  }
}
</script>
```

공통 필드:

- `document`: 문서 제목
- `mode`: `decision` 또는 `report`
- `asOf`: 문서가 사실로 삼은 기준일
- `audience`: 수신자 목록
- `summary`: 본문의 한 문장 결론
- `sources`: 본문 출처 ID와 원문 정보

의사결정 모드 권장 필드:

- `fixedDecisions`: 이미 확정된 사항 목록
- `remainingDecision`: 이번 문서에서 정할 내용
- `constraints`: 선택을 가르는 제약 목록
- `recommendation`: 권고안과 판단 기준
- `options`: 선택지와 장단점

보고 모드 권장 필드:

- `findings`: 핵심 발견 사항
- `implications`: 영향과 위험
- `nextActions`: 후속 작업
- `limitations`: 한계와 미확인 사항

출처가 로컬 내부 자료뿐이라 URL을 넣을 수 없으면 `url` 대신 독자가 접근 가능한 문서 식별자와 설명을 사용한다. 팀 공유 문서에 개인 로컬 경로는 넣지 않는다.
