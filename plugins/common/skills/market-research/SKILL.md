# Market Research

시장 조사의 결론은 다음 사람이 그 숫자를 다시 셀 수 있을 때만 쓸모가 있다. 이 스킬은 출처 접근 확인부터
원문 확보·코딩·대조까지를 원자료가 남는 순서로 진행하고, 자동으로 못 읽는 출처는 사람 손을 빌려 캡처한다.

**핵심 원칙**:
- 원자료를 작업 폴더에 둔다. 검색 결과 원본, 본문 저장본, 캡처, 판독본, 서브에이전트 보고 원문을 `/tmp`나
  대화에만 두지 않는다. 결론의 숫자는 저장본에서 다시 셀 수 있어야 한다.
- 막힌 출처는 우회하지 않는다. 내부 API 호출, 로그인 자동화, 봇 차단 회피, 자동 스크롤 크롤링은 하지 않는다.
  플랫폼 약관과 도구 안전 정책을 어기게 되고, 우회 시도 자체가 도구 분류기에 거부된다. 막히면 사람이 여는 단계로 내려간다.
  스크립트는 브라우저인 척하지 않는 UA로, 공개 검색 결과 페이지만 요청 사이 간격을 두고 한 번씩 받는다.
- 증거 수준을 사례마다 적는다. 원문 저장본, 스크린샷 판독본, 이미지와 직접 대조한 것은 믿을 수 있는 정도가 다르다.
- 0건은 "없음"이 아니라 "이 검색어·출처 범위에선 안 보임"이다. 결론에 범위를 함께 쓴다.

## 실행 절차

작업 폴더를 먼저 정한다(프로젝트 지침에 조사 자료 위치가 있으면 따른다). 기본 구조:

```
<작업 폴더>/
├── raw/            검색 결과 원본, 후보·선별 목록, 본문, 캡처, cases.json, verify.tsv
├── scripts/        이 조사에서 쓴 수집·집계 스크립트(복사해 고친 것 포함)
└── <결론 문서>
```

이 스킬의 스크립트는 현재 `SKILL.md`가 있는 디렉터리의 `scripts/`에 있다(아래 `<scripts>`). 셸 실행 전 절대 경로로 바꾼다.
모델이 대신할 수 없는 핵심은 창 캡처(`capture_helper.py`)와 인용 대조(`verify_quotes.py`)다. 후보 수집·접근 확인 스크립트는
같은 일을 매번 같은 방식으로 하게 하는 보조다.

### 1. 질문과 판정선

질문마다 "답이 나오면 무엇을 정하나"와 판정선(몇 건이면 어느 쪽으로 기우나)을 적는다. 계획서가 있으면 그것을 쓰고,
없고 질문이 셋 이상이거나 결론이 되돌리기 비싼 결정에 쓰이면 `work-plan`으로 먼저 설계한다.
스킬 호출 도구가 있으면 대상 스킬을 호출한다. 없으면 사용 가능한 스킬 목록에서 대상 지침을 찾아 읽고 현재 에이전트가 그대로 수행한다.

반대 사례(이미 해결됐다, 필요 없다, 다른 수단으로 한다)를 찾을 검색어도 이때 함께 정한다. 찾는 쪽 사례만 모으면 결론이 표본에서 나온다.

### 2. 출처 접근 확인

출처마다 샘플 주소 하나로 어디까지 자동으로 읽히는지 먼저 본다. 수집 도중에 막히는 것을 알면 그때까지 쓴 시간이 버려진다.

```bash
python3 <scripts>/probe_access.py --urls raw/access_urls.tsv --out raw/access.tsv
```

`access_urls.tsv` 칸은 `source`, `url`이다. curl 결과를 본 뒤 같은 주소를 현재 하네스에 있는 브라우저 도구(내장 브라우저, 브라우저 확장)로 열어 보고 `access.tsv`의
`browser`·`extension` 칸을 `열림`·`정책 차단`·`로그인 요구`·`도구 없음` 중 하나로 채운다. 그 결과로 출처마다 접근 단계를 하나 정한다:

| 단계 | 언제 | 원문 확보 방법 |
|---|---|---|
| 자동 | curl이나 웹 읽기 도구로 본문이 나온다 | 본문을 받아 `raw/`에 저장 |
| 브라우저 도구 | curl은 막히고 에이전트 브라우저로는 열린다 | 페이지 글자를 읽어 저장 |
| 반자동 캡처 | 에이전트 브라우저가 정책으로 막히거나 로그인이 필요하다 | 사람이 열고 `capture_helper.py`로 창 캡처 |
| 제외 | 사람도 열 수 없다(회원 전용·삭제) | 건너뛴 수를 세어 결론에 적는다 |

접근 단계별 상세, 반자동 캡처를 사람에게 맡기는 법, 출처별로 확인된 사실은 [references/acquisition.md](references/acquisition.md)에 있다.
반자동 캡처를 쓰는 출처가 있으면 4단계 전에 읽는다.

### 3. 후보 수집

검색 결과 페이지가 자동으로 받아지는 출처는 스크립트로 모은다. 받은 검색 결과 페이지는 원본으로 남는다.

```bash
python3 <scripts>/collect_candidates.py --queries raw/queries.tsv --out raw/candidates
```

`queries.tsv` 칸은 `group`(질문·주제), `query`, `source`다. 프리셋은 `naver_cafe`·`naver_blog`·`naver_kin`이다.
다른 출처는 `--search-url`과 `--link-pattern`을 준다. 사람이 브라우저에서 저장한 검색 결과 페이지(HTML)가 있으면
`collect_candidates.py --from-html <저장 폴더> --source <프리셋> --group <질문> --out raw/candidates`로 같은 표를 만든다.
한 글이 여러 질문·검색어에 걸리면 `group`·`query` 칸에 `|`로 함께 적힌다.
"링크 0건"이 찍힌 페이지는 저장본을 열어 차단 화면인지, 패턴이 틀렸는지 본다.
검색 결과 페이지도 막힌 출처는 그 페이지를 캡처 목록에 넣어 사람이 찍고, 캡처에서 후보를 옮겨 적는다.
경쟁 제품·가격처럼 공식 페이지가 출처면 웹 검색 도구로 후보 주소를 모으고 같은 `candidates.tsv` 칸으로 적는다.

### 4. 선별

후보의 발췌만 보고 본인 경험·실제 제품 사실인지, 홍보·광고·복사 글인지 가려 `raw/shortlist.tsv`(칸: `id`, `url`, `title`,
`group`, `reason`)에 남긴다. 서브에이전트에 맡겨도 된다. 이 파일이 그대로 캡처 목록이 된다. 질문별로 묶어 두면 사람이 캡처할 때
같은 주제를 이어서 읽는다.

### 5. 원문 확보

자동·브라우저 도구 단계 출처는 본문을 `raw/sources/<id>.html` 또는 `.txt`로 저장한다.
반자동 캡처 단계 출처는 사람에게 아래 명령 하나를 주고, 첫 글 한 장을 찍으면 알려 달라고 한다.
첫 장을 직접 열어 브라우저 창이 맞게 찍혔는지 확인한 뒤 나머지를 진행시킨다.
이 명령은 키 입력을 받으므로 에이전트가 실행하지 않고 사람이 자기 터미널에서 실행한다.

```bash
python3 <scripts>/capture_helper.py --list raw/shortlist.tsv --out raw/captures
```

macOS 전용이고 기본 브라우저는 Google Chrome이다. 다른 브라우저면 `--app <앱 이름>`을 붙인다. macOS가 아니면 사람에게
운영체제 캡처 기능으로 찍어 `raw/captures/<id>_<n>.png`로 저장해 달라고 하고, 건너뛴 글은 `capture_log.tsv` 칸(`id`, `url`, `files`, `status`)으로 직접 적는다.

### 6. 판독·코딩

캡처는 서브에이전트에 글별로 나눠 옮겨 적게 하고(`raw/captures/<id>.txt`), 보고 원문을 저장한다.
서브에이전트 위임이 불가능하면 직접 이미지를 읽어 옮겨 적는다.
사례는 `raw/cases.json`에 적는다. 사례 `id`는 `shortlist.tsv`의 `id`를 그대로 쓰고, 댓글은 `<id>-c<n>`으로 둔다. 칸·증거 수준·행동/불편/추론 구분·제품 사실표는
[references/case-coding.md](references/case-coding.md)를 따른다. 코딩 전에 읽는다.

### 7. 대조

```bash
python3 <scripts>/verify_quotes.py raw/cases.json
python3 <scripts>/verify_quotes.py raw/cases.json --sample 2
python3 <scripts>/verify_quotes.py raw/facts.json
```

첫 명령은 모든 인용이 저장본에 있는지 보고 `raw/verify_cases.tsv`를 쓴다. 셋째 명령은 제품 사실표를 같은 방식으로 대조해 `raw/verify_facts.tsv`를 쓴다. 불일치는 고치거나 사례에서 뺀다. 스크린샷 판독본은 판독본 자체와 대조되므로,
두 번째 명령이 고른 사례를 캡처 이미지와 직접 나란히 보고 `evidence`를 `직접 대조`로 바꾼다.
서브에이전트가 코딩한 칸은 원문을 다시 보고 확인하고, 바꾼 칸은 `changed`에 남긴다.

### 8. 집계와 결론

집계는 `scripts/`에 스크립트로 남겨 `cases.json`에서 다시 셀 수 있게 한다. 결론 문서의 형식은 조사마다 정한다.
결론에 반드시 둘 것: 질문별 건수와 그 분모, 출처별 접근 단계와 건너뛴 수, 증거 수준별 건수, 반대 사례, 0건인 질문과 그 범위,
사례와 따로 센 제품 사실표.

### 9. 독립 검증

결론 문서를 사용자에게 보이기 전에 `critique-research`로 넘긴다. 최소 수치 재현 관점(원자료로 다시 세기)과 논증 구조 관점을 넣는다.
스킬 호출 도구가 없으면 사용 가능한 스킬 목록에서 대상 지침을 찾아 읽고 현재 에이전트가 그대로 수행한다.

## 행동 원칙

- 사람에게 맡기는 일은 한 번에 모은다. 캡처 목록을 다 만든 뒤 한 번 요청하고, 도중에 글마다 묻지 않는다.
- 브라우저 도구가 막힌 출처를 다른 도구·다른 주소로 다시 열어 보지 않는다. 한 번 막혔으면 반자동 단계로 내려간다.
- 검색 결과 발췌만으로 사례를 세지 않는다. 발췌는 선별에만 쓰고, 사례는 원문을 확보한 것만 센다.
- 조사 도중 범위를 넓혔으면(사례 수, 출처) 결론의 "계획과 달라진 점"에 적는다.
