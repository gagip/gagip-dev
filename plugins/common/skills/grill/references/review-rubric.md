# grill 검수 기준

인터뷰 맥락을 모르는 상태에서 사용자 요청 원문, 세션 문서의 명세, 마지막 응답만 읽고 채점한다. 명세 칸이 있는지는
코드가 이미 검사하므로 여기서는 내용만 본다. 항목마다 통과·미통과와 인용을 답한다.

## 항목

| # | 기준 | 통과 조건 |
|---|---|---|
| 1 | 찾을 수 있는 사실을 묻지 않았는가 | 레포 파일·코드로 확인할 수 있는 것(테스트 명령, 기존 구조)을 사용자에게 묻지 않았다 |
| 2 | 질문만 읽고 답할 수 있는가 | 물은 질문마다 배경·선택지·권장안이 붙어 있다. 묻지 않았으면 묻지 않은 이유가 요청과 맞다 |
| 3 | 명세가 요청보다 넓지 않은가 | 요청에 없는 기능·파일·플랫폼·예외 처리를 명세에 더하지 않았다 |
| 4 | 완료 기준을 증거로 확인할 수 있는가 | 완료 기준이 실행할 명령과 기대 결과처럼 관찰할 수 있는 말이다 |
| 5 | 합의 요약이 구분돼 있는가 | 사용자가 정한 것, 권장안대로 간 것, 남은 가정이 섞이지 않는다 |
| 6 | 요청의 제약을 지켰는가 | 요청이 금지한 것(다른 파일 수정, 구현, 커밋 등)을 명세나 응답이 어기거나 하겠다고 하지 않는다 |

## 답 형식

```
#<번호> 통과 | 미통과
근거: "<명세나 응답에서 인용한 문장>"
고칠 문장: <미통과일 때>
```
