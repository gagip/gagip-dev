# 검증·이해를 다루는 스킬의 평가

완료 판정이나 학습자 이해를 다루는 스킬(예: `dev`)은 절차를 밟았는지만 보면 부족하다. 위험한 쪽은
**틀렸는데 완료했다고 말하는 경우**라서, 그런 경우를 일부러 만들어 평가한다. 예시는 `dev`의
`evals/verification_*.py`와 `scripts/test_verify.py`다.

## 평가할 실패 유형

- 실패·미실행을 통과로 보고하거나, 통과 뒤 코드를 바꾸고 옛 증거를 쓰는 경우
- 테스트·기대값을 약화해 통과시키거나, 요구사항과 무관한 검사로 성공하는 경우
- 실제 코드의 실패 처리와 설명이 다르거나, 작은 수정에 불필요한 문서·퀴즈를 강제하는 경우

## 코드로 평가할 것과 판단으로 평가할 것

- 코드로 평가한다: 실행 상태, 로그, 코드 지문, 실패 시 완료 거부.
- 코드 대조와 정성 평가로 판단한다: 검사와 요구사항의 대응, 설명의 정확성·간결성.

## 지킬 점

- AI 설명과 AI 퀴즈가 서로 맞는지만으로 정확성을 인정하지 않는다. 둘이 같은 오해를 공유할 수 있다.
- baseline은 같은 채점 기준을 쓰고, 발동 여부만으로 차이를 만들지 않는다.
- 평가 케이스가 통과해도 학습자 이해가 향상됐다고 주장하지 않는다. 케이스는 거짓 완료를 막는지만 보여 준다.
