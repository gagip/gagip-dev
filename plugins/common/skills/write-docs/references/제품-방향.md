# 제품 방향 문서(PRODUCT.md) 가이드라인

기본 독자는 방향을 정하는 사람과 기능을 맡은 사람이다. 새 요청을 이 문서와 대조해 진행할지, 보류할지, 방향을 바꿔야 할지 가를 수 있어야 한다. 제품마다 한 편만 두고 기능별 진행 상황은 쌓지 않는다.

## 상태

항목마다 상태를 표시한다.

- **확정**: 정하는 사람이 정했고 출처가 있다.
- **가설**: 관찰이 부족하거나 아직 정하지 않았다. 무엇을 보면 확정하거나 버릴지 함께 쓴다.
- **미합의**: 자료나 사람 사이에 답이 갈린다. 갈리는 안, 정할 사람, 이것에 달린 기능을 쓴다.

지금 코드에 있다는 것은 현재 동작의 근거일 뿐 방향이 확정됐다는 근거가 아니다.

## 절 구성

1. **목적**: 이 제품이 왜 있고 사용자에게 어떤 변화를 만들려 하나.
2. **대상 사용자와 문제**: 누가 어떤 상황에서 무엇을 못 하나. 대상이 아닌 사람도 쓴다.
3. **핵심 가치**: 다른 방법보다 나은 것.
4. **지금 집중할 문제**: 먼저 풀 것과 이유.
5. **원칙**: 선택이 갈릴 때 어느 쪽을 고르는지. 「A와 B가 갈리면 A, 잃는 것은 …」처럼 쓴다. 누구나 동의하는 말은 뺀다.
6. **비목표**: 지금 의도적으로 하지 않는 사용자·문제·범위와 이유.
7. **성공 기준**: 사용자의 어떤 변화가 보이면 가치를 줬다고 보는지. 합의 전 값은 「제안」으로 표시한다.
8. **미합의**: 갈리는 안, 정할 사람, 달린 기능.
9. **확인 필요**: 무엇을 누구에게 확인할지.
10. **변경 이력**: 날짜, 바뀐 항목, 이유와 근거, 영향받는 기능.

## 경계

- 화면 배치, 기능 상세, 일정, 구현 방식은 쓰지 않는다.
- 기존 자료에서 방향이 갈리면 하나로 매끄럽게 합치지 않고 미합의에 올린다.
- 프로젝트 지침이나 사용자가 파일 이름·위치를 정하지 않았으면 `product/PRODUCT.md`에 둔다.
