# 기획 계획서(PRD) 가이드라인

기본 독자는 이 기능을 함께 만드는 기획·디자인·개발 담당과 승인자다. 왜 만드는지와 무엇이 되어야 하는지를 쓰고, 어떻게 구현할지는 쓰지 않는다.

## 절 구성

1. **배경과 문제**: 지금 사용자가 겪는 일을 사실과 수치로 쓴다. 출처 없는 수치는 쓰지 않는다.
2. **대상 사용자**: 누가, 어떤 상황에서 쓰는지. 확정 전이면 그렇게 밝힌다.
3. **목표와 성공 기준**: 무엇이 달라지면 성공인지, 어떤 값으로 언제 재는지. 합의 전 값은 「제안」으로 표시한다.
4. **범위**: 포함과 범위 외를 나란히 쓴다.
5. **요구사항**: 사용자 시나리오 단위로 번호를 붙이고 필수·선택을 표시한다. 시나리오마다 정상과 실패 동작을 함께 쓴다.
6. **화면과 흐름**: 시안 또는 현재 화면 캡처와 흐름. 시안이 정해지지 않았으면 그렇게 쓴다.
7. **제약**: 규제, 서버·외부 의존, 일정. 각각 바꿀 수 있는지와 누가 정하는지를 쓴다.
8. **확인 필요**: 무엇을 누구에게 언제까지 확인할지.

## 경계

- 구현 방식, 작업 순서, 담당 배정은 쓰지 않는다.
- 문서가 승인되면 정해진 내용은 기능 명세로, 할 일은 이슈로 옮긴다. 이 문서에 진행 상황을 쌓지 않는다.
- 다른 팀 작업이 필요하면 의도와 요구사항만 쓴다. 성능 수치와 논의 이력은 넣지 않는다.
