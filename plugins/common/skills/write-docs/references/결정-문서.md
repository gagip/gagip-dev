# 결정 문서 가이드라인

기본 독자는 결정하는 사람과, 나중에 왜 이렇게 됐는지 찾는 사람이다. 첫 문단만 읽어도 무엇을 정했는지(또는 정해야 하는지) 알 수 있어야 한다.

## 상태

제목 바로 아래에 상태를 쓴다.

- **결정 전**: 사용자나 결정권자가 아직 정하지 않았다. 「결정」, 「확정」으로 쓰지 않고 「권장안」으로 쓴다.
- **결정됨**: 누가 언제 정했는지 쓴다. 요청이나 회의 기록으로 확인될 때만 쓴다.

## 절 구성

1. **요약**: 결정 또는 권장안과 이유 한두 문장.
2. **상황**: 왜 지금 정해야 하는지, 정하지 않으면 무슨 일이 생기는지.
3. **현재 동작**: 지금 어떻게 되어 있는지 실제 값으로.
4. **선택지**: 표로 비교한다. 현재 유지를 선택지에 넣는다. 각 칸에 할 일, 비용, 위험을 값으로 쓴다. 출처로 댈 수 없는 값은 「미확인」으로 쓰고 확인 필요에 올린다. 견본의 숫자는 형식 예시다.
5. **결정과 이유**: 판단 기준과 왜 다른 선택지를 버렸는지. 서로 관계없는 이유를 하나의 인과로 묶지 않는다.
6. **다시 볼 조건**: 어떤 값이나 상황이 바뀌면 결정을 다시 보는지.
7. **후속**: 정해진 내용이 옮겨 갈 기준 문서와 이슈.
8. **확인 필요**: 결정을 바꿀 수 있는 미확인 사실. 없으면 뺀다.

독자가 비개발자이고 전문어가 많으면 요약 뒤에 용어 풀이를 둔다.

## 견본

```markdown
상태: 결정 전

**요약**: 현재 구조 유지를 권장함. 통일해도 사라지는 구성 요소가 없고, 핵심 동작을 다시 만드는 비용이 남음

| 선택지 | 할 일 | 비용 | 위험 |
| --- | --- | --- | --- |
| 현재 유지 | 없음 | 없음 | 발송 경로 2개 유지 |
| 통일 | 플러그인 교체, 알림 이동 재구현 | 2주 | 기존 사용자 토큰 재등록 |
```
