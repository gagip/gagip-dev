## [0.23.0] - 2026-08-21

### ♻️ Refactor
- **report/apply-review/module-review/retrospective/create-pr/worktree-scaffold**: 산출물 기본 저장 위치를 `private/`에서 점으로 시작하는 `.private/`로 바꿨다. 파일 탐색기·`ls` 기본 목록에서 숨겨져 작업 산출물이 소스 트리를 가리지 않는다. **이미 `private/`(점 없음)를 쓰는 프로젝트는 그 폴더를 계속 쓰도록** 각 스킬에 명시해, 기본값 변경만으로 산출물이 두 폴더로 갈리지 않게 했다. `report`에는 새로 `.private/`를 만들었을 때 프로젝트 `.gitignore`에 항목이 있는지 확인하는 절차를 추가했다 (`31a2577`)

### ✨ Feat
- **coding-philosophy**: 코드 품질 판정의 공통 기준(개인 코딩 철학)을 독립 스킬로 신설했다. 기존에는 `mobile:android-review`의 `references/` 안에 있어 다른 스킬이 참조할 수 없었다. 기존 7장(계약 프로그래밍·빠른 실패·구조적 프로그래밍·에러 경계·에러 표현·테스트 철학·주석)에 더해 4개 장을 추가했다 — ⑧공개 인터페이스 최소화(운영 코드 호출처가 판정 기준이며 테스트 전용 사용은 근거가 아니다), ⑨시그니처 자기설명(방향·단위 없는 파라미터명과 raw map/tuple 금지), ⑩테스트 가능성은 설계에서 나온다(가시성이 아니라 의존성 주입·순수 함수·부수효과 격리), ⑪가짜 테스트 금지(프로덕션을 호출하지 않고 자기 자신과 비교하는 테스트). 기존 장에도 "형제 요소 중 하나만 검증이 빠진 비대칭은 취향 차이가 아니라 결함"이라는 판정 규칙을 심었다 (`b829487`)
- **module-review**: 모듈·패키지 단위 순차 리뷰 전용 스킬을 추가했다. 변경분(diff)이 아니라 모듈이 밖으로 내놓는 공개 계약을 대상으로 ①공개 표면 열거 ②public 최소화 ③시그니처 자기설명 ④계약 프로그래밍 ⑤실패 방식 통일 ⑥테스트 가능한 구조 ⑦테스트 커버리지·정직성 순으로 점검한다. 모듈 하나를 마칠 때마다 사용자 확인을 받고, 발견은 메모 파일에 축적하되 코드는 수정하지 않으며(수정은 `apply-review` 소관), 서브에이전트 독립 검증과 Tier triage로 마무리한다. 지적마다 실패 시나리오를 요구하고 못 쓰면 취향이므로 뺀다. 판정 기준은 `common:coding-philosophy`를 스킬 이름으로 참조한다 — 스킬 디렉터리는 스킬마다 달라 플러그인을 넘는 파일 참조 경로가 없기 때문 (`b829487`)
