# marketing

브랜드 포지셔닝·문구·네이밍을 **여러 관점에서 따로 검토**하는 도구 묶음이다. 한 컨텍스트가 혼자 카피를 쓰면 자기 결과물을 옹호하게 되므로, 관점을 나눠 각자 독립된 근거로 판단하게 한다.

## 전제 — 이 플러그인은 제품 정보를 갖고 있지 않다

에이전트는 **지식베이스 파일 경로를 받아** 거기서 제품의 제약·재료를 읽는다. 제품 지식은 그 제품의 문서 저장소에 남고 이 플러그인에는 들어오지 않는다. 그래서 어떤 제품에도 쓸 수 있고, 회사 자료가 플러그인 레포로 새지 않는다.

지식베이스가 없으면 `brand-knowledge-base` 스킬로 먼저 만든다. 이게 첫 실행에 한 번 드는 비용이고, 그 뒤로는 재사용한다.

## 스킬

| 스킬 | 설명 | 트리거 예시 |
|---|---|---|
| `brand-knowledge-base` | 제품 지식베이스를 만든다. 확정 사실·금지선·톤·사용자 발화·현행 문구를 수집하고 번들된 일반 이론을 붙여 한 파일로 | "브랜딩 지식베이스 만들어줘" |
| `brand-brainstorm` | 지식베이스를 주입해 여섯 관점을 병렬로 돌리고, 관점 간 충돌까지 정리해 종합 | "여러 관점으로 카피 검토해줘" |

## 에이전트

| 에이전트 | 하는 일 |
|---|---|
| `brand-positioning-strategist` | 어느 범주(서랍)에 들어갈지, 누구를 밀어낼지, 무엇을 포기할지 |
| `brand-verbal-identity` | 태그라인·서브카피·화면 문구를 실제 문장으로 |
| `brand-behavior-designer` | 그 문구가 요구하는 행동이 사람에게 어떻게 읽히고 어디서 끊기는지 |
| `brand-skeptic` | 제안된 문구를 실제 사용자 입장에서 깨뜨린다 |
| `brand-market-benchmarker` | 경쟁·인접 제품이 실제로 쓰는 문구를 원문으로 수집해 대조 |
| `brand-naming-ritual` | 반복 행동·구간·추상어에 이름을 붙인다 |

## 쓰는 법

```
/brand-knowledge-base    # 처음 한 번. 지식베이스 파일을 만든다
/brand-brainstorm        # 갈림길이 생길 때마다. 여섯 관점을 돌린다
```

개별 관점만 필요하면 에이전트를 직접 부른다 — 예: 문구 대안만 필요하면 `brand-verbal-identity`, 이미 나온 안을 깨뜨리고 싶으면 `brand-skeptic`.

## 설계상 정한 것

- **에이전트는 파일을 수정하지 않는다.** 전부 읽기 전용이고 산출물은 메시지로만 낸다. 반영 여부는 사람이 정한다.
- **일반 이론은 박제, 시장 실물은 조회.** 프레임워크·연구·판정 기준은 잘 안 변해서 번들 문서로 고정했고, 경쟁사 문구는 낡으므로 벤치마커가 그때그때 가져온다.
- **관점 수를 늘리는 것이 품질을 만들지 않는다.** 이 구성이 결과를 낸 이유는 관점 개수가 아니라 주입된 지식의 구체성이었다. 새 관점을 더하기 전에 지식베이스를 채우는 편이 낫다.
